# 매입 → 판매 흐름 대시보드

매입 풀 바코드와 판매 모델번호를 연결하여 매입 후 언제 얼마나 팔렸는지 보는 한국어 Streamlit 시안입니다. 실제 현재 재고를 산출하는 앱은 아닙니다. 내장 시연 데이터는 전부 **가상**이며 사용자 실제 자료가 아닙니다.

## GitHub에 한 번 올리고 엑셀만 추가하기

1. ZIP을 풀고 `sales-dashboard` 폴더 **안의 파일과 폴더**를 GitHub 저장소 최상위에 올립니다. `app.py`, `loader.py`, `engine.py`, `demo.py`, `requirements.txt`가 같은 위치에 있어야 합니다.
2. Streamlit Community Cloud에서 해당 저장소·브랜치와 `app.py`를 선택해 배포합니다. GitHub 자체는 Streamlit 서버를 실행하지 않습니다.
3. 이후 엑셀을 **app.py 옆 또는 data 폴더**에 업로드하고 Commit changes로 저장하면 됩니다. `data/2026/` 같은 하위 폴더도 읽습니다. 별도 앱 업로드나 코드 수정은 필요 없습니다.
4. 앱 기본 모드는 `GitHub 저장소 엑셀 자동 연결`입니다. 연결된 파일 목록을 펼쳐 확인하세요. 배포 서비스가 저장소 변경을 동기화한 후 앱이 다시 실행될 때 새 엑셀을 읽습니다. 열려 있는 화면에서는 `저장소 파일 다시 읽기`를 누르세요. 파일 변경이 반영되지 않으면 Community Cloud에서 Reboot app을 실행하세요.

로컬 실행은 로컬 파일을 읽습니다. 로컬 앱이 GitHub를 직접 내려받지는 않으므로 변경을 내려받은 뒤 다시 읽어야 합니다. 앱에 GitHub 토큰을 넣을 필요는 없습니다.

공개 GitHub 저장소에 올린 엑셀은 누구나 볼 수 있습니다. 실제 거래 자료를 올릴 저장소와 앱의 공개 범위를 먼저 정하세요.

```text
app.py
loader.py
engine.py
demo.py
requirements.txt
data/
  매입_10.31.xlsx
  전년도 판매.xlsx
  금년도 판매_10.31.xlsx
```

## 실행

Python 3.11 또는 3.12 권장. 프로젝트 폴더에서:

```shell
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

엑셀이 없어도 왼쪽에서 `가상 예시 데이터`를 선택하면 2025/2026 시안을 볼 수 있습니다. `내 엑셀 업로드` 모드는 임시 확인용으로 유지했습니다.

## 엑셀 형식

- `.xlsx`, `.xls` 지원. 모든 시트의 첫 20행에서 헤더를 찾습니다. 잠금 임시 파일 `~$...`은 무시합니다.
- 매입: `일자-No.`, `품목코드`, `품목명(규격)`, `수량`, `단가`, `공급가액`, `부가세`, `합계`, `거래처명`.
- 판매: 1행 회사명, 2행 `일자`, `판매처명`, `창고명`, `품명 및 규격`, `모델번호`, `COLOR`, `SIZE`, `수량`, `단가`, `공급가액`, `부가세`, `합계`.
- 필수 열은 매입의 일자-No./품목코드/수량, 판매의 일자/모델번호/수량입니다. 거래처 누락은 미상으로 표시합니다.
- `매입_10.31`, `전년도 판매`, `금년도 판매`, `매출_10.31` 이름을 인식하며, 분류는 실제 헤더가 우선입니다. 파일명의 전년도/금년도를 현재 연도에 맞춰 강제로 바꾸지 않습니다. 엑셀 날짜의 2025/2026을 사용합니다.
- `2026/10/31-1` 전표 날짜, `2026-10-31`, `2026.10.31`, `20261031`, 엑셀 날짜 셀·일련번호를 처리합니다. 연도 없는 `10/31`은 추측하지 않고 오류로 분리합니다.
- 쉼표·공백 숫자, 괄호 음수 `(1,200)`, 코드의 앞뒤/중간 공백과 대소문자를 정리합니다. 바코드가 엑셀에서 이미 숫자로 바뀌어 앞자리 0이 소실됐다면 복구할 수 없습니다.
- 소계·총계·합계·누계/영문 total 표시 행을 제외합니다. `합계`라는 **열 자체는 정상 열**입니다. 날짜와 코드가 채워진 합산 행도 표식이 있으면 제외합니다. 아무 표식 없는 합산행은 일반 거래와 구분할 근거가 없으므로 원본에서 표식을 추가해야 합니다.
- 날짜·코드·수량 오류, 읽지 못한 파일/시트, 반품, 중복 후보는 검증 탭에서 원본 파일·시트·행 번호와 함께 확인합니다.

## 중복과 최신 파일

바이트가 같은 파일은 한 번만 읽습니다. 여러 파일·시트의 전체 원본 열 값이 같은 행은 기본적으로 중복 후보로 제외하되, 한 시트 안의 동일 거래가 여러 건이면 그 반복 횟수는 보존합니다. 파일명에 적힌 최신 날짜만 보고 이전 파일 전체를 버리지는 않습니다.

자동 중복 제외는 전표 고유번호가 없는 판매자료에서 완벽할 수 없습니다. 같은 값의 서로 다른 거래가 겹치면 중복 제외를 끄고 확인하세요. 수정된 누적 파일은 기존 파일과 값이 달라 별도 거래로 남을 수 있으므로, **누적 최신본으로 갱신할 때는 같은 기간의 예전 누적 파일을 저장소에서 제거하고 교체하는 방식**을 권장합니다. 2025 판매와 2026 판매처럼 기간이 다른 파일은 함께 둡니다.

## 모델 연결과 분석 원칙

- 판매에 실제 존재하는 모델번호 목록을 매입 코드의 접두사와 비교합니다. 길이를 고정하지 않습니다. `TF31KS019BLK008` → `TF31KS019`.
- 여러 후보가 맞으면 가장 긴 것을 선택하고 모든 후보를 검증 탭에 남깁니다. 예: `ABC`와 `ABC123`이면 `ABC123` 우선. 접두사가 실제 모델 경계라는 보장은 없으므로 다중 후보를 확인해야 합니다.
- 미매칭 매입을 억지로 묶지 않습니다. 판매자료에 한 번도 등장하지 않은 모델은 자동으로 유추하지 않습니다. 연결되지 않은 판매 모델도 별도 표시합니다.
- 전체 입력에서 기준일까지 FIFO를 먼저 계산하고 화면 필터를 나중에 적용합니다. 2026 판매만 보더라도 2025 입고와 판매 이력은 계산에 남습니다.
- 모델별 오래된 입고부터 판매에 배분합니다. 같은 날은 입고가 먼저이며 같은 날 여러 매입처는 파일/시트/행 순서를 따릅니다. 실제 시각·출고 지정이 없어 모두 추정입니다.
- 입고 전 판매 또는 입고를 초과한 판매는 미배분으로 남깁니다. 미래 입고로 소급 충당하지 않습니다. 기초재고·이동·폐기 정보가 없어 실제 현재 재고와 같지 않습니다.
- 음수 매입/판매와 0 수량은 원장·검증 표에 남기고 FIFO 분모·분자에서 제외합니다. 원거래를 모르는 반품을 임의의 입고에 되돌리지 않습니다. 따라서 소진율은 반품을 반영한 순소진율이 아니며, 반품이 많을수록 과대평가될 수 있습니다. 날짜별 원장 차트는 반품을 포함한 순수량입니다.
- 매입처별 판매는 배분된 판매만 나타냅니다. 매입처가 없는 전체 판매 원장에는 매입처 필터를 적용하지 않습니다.
- 30/60/90/180일 소진율은 선택한 입고 기간의 입고 코호트 기준입니다. 기준일까지 해당 일수가 경과한 입고만 분모로 삼고 입고 당일부터 N일 후까지 배분된 양수 판매를 분자로 삼습니다. 아직 기간이 안 지난 입고는 별도 수량으로 표시하고 분모가 0이면 빈 값입니다.
- 코호트 탭에는 판매연도 필터를 적용하지 않습니다. 선택 입고 이후 연도를 넘기는 판매도 포함해야 하기 때문입니다. 업로드된 판매 자료가 관찰 종료일까지 완전하다는 가정이며 파일 누락은 소진율을 낮출 수 있습니다.

## 화면

전체 흐름 / 매입처별 판매 / 입고 코호트 소진율 / 모델 상세 / 데이터 검증. 분석 기준일, 표시 날짜, 판매연도, 매입처, 모델을 선택할 수 있으며 결과 표는 CSV로 내려받을 수 있습니다. 내부 컬럼 `date`는 거래일, `qty`는 수량, `partner`는 원장 거래처, `supplier`는 추정 매입처, `days`는 입고 후 경과일입니다.
